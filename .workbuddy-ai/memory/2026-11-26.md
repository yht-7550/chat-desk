# 2026-11-26

## 从零搭建 ChatDesk：静态产物桌面外壳（Vite + Vue3 + Pinia + Tauri 2）

**需求**：用 Vite + Vue3 + Pinia + Tauri 建一个项目，作为「另一个静态打包产物」的桌面端实现。

**架构决策**
- 外壳（Vue3 应用）自己就是 Tauri 前端；静态产物放在 `public/webapp/`，通过 `iframe src="/webapp/index.html"` 承载。
  - 否掉了 Tauri 自定义协议（`app://`）方案：v2 在 Windows 上实际走 `http://<scheme>.localhost`，跨平台 URL 不一致，且本机无 Rust 无法编译验证。
  - 否掉了「产物放根目录 + 外壳放子目录」方案：需要改 Vite 多页输出，太绕。
- 产物挂子路径的核心风险是绝对路径 `/assets/...` 失效 → `scripts/sync-webapp.mjs` 复制后重写 HTML 里的 `src="/"`、`href="/"` 为相对路径，并扫描 CSS/JS 残留绝对路径给警告。
- 缩放用「iframe 放大画布 + transform: scale」实现，不侵入产物文档，跨域也生效。
- 所有桌面能力集中在 `src/lib/tauri.ts`，用 `isTauri()`（检测 `__TAURI_INTERNALS__`）降级，浏览器里 `npm run dev` 可直接调 UI。
- 无边框窗口 `decorations:false`，标题栏用 `data-tauri-drag-region`；窗口控制走 `@tauri-apps/api/window`，权限在 `src-tauri/capabilities/default.json` 显式声明。
- devtools 用自定义 Rust 命令 `toggle_devtools`（cfg 限定 debug），避免猜 `core:webview:allow-*` 权限名。

**环境坑**
- 本机 **没有 Rust/MSVC**（只有 Node 22 + WebView2），`tauri dev/build` 无法验证；前端部分已用 `vue-tsc` + `vite build` + Edge headless 截图验证。
- Node 22 的 `fs.cpSync` 在**源路径含中文**（如 `C:\Users\安宣\...`）时直接崩溃（退出码 127，无报错）→ 改为手写递归 `copyDir`（readdirSync + copyFileSync）。
- `vue-tsc` 的 project references + `tsconfig.node.json` 会报 TS6305/TS6310 → 改单一 tsconfig，`types: ["vite/client","node"]` 并装 `@types/node`。
- 图标用纯 Node 手写 PNG/ICO/ICNS 编码器生成（`scripts/gen-icons.mjs`），不依赖 cargo/svg 工具。

**验证结果**：`npm run build` 通过（101KB JS / 13KB CSS）；dev 与 preview 下截图确认明暗主题、设置抽屉、iframe 承载、状态栏均正常。

**待用户处理**：装 Rust（rustup + MSVC C++ 生成工具）后才能 `pnpm tauri:dev`；替换 `src-tauri/icons` 与 `identifier` 后即可打包。

## 后续：迁移 pnpm + 接入真实产物 + 首次 Rust 编译验证

- **包管理器换成 pnpm 11**：删 `package-lock.json`/`node_modules` 后 `pnpm install`；`package.json` 加 `packageManager: pnpm@11.22.0`；
  `tauri.conf.json` 的 beforeDev/beforeBuild 改成 `pnpm dev` / `pnpm build`。
  - pnpm 11 默认不跑依赖构建脚本，`esbuild` 需在 `pnpm-workspace.yaml` 的 `allowBuilds` 里显式 `esbuild: true`（否则 vite build 缺二进制）。

- **Rust 环境就绪**：rustc 1.100.0 x86_64-pc-windows-msvc，cargo 在 `~/.cargo/bin`（默认 bash PATH 里没有，命令需 `export PATH="$HOME/.cargo/bin:$PATH"`）。
